# Непрерывный контекст, исправления телефонной приёмки и поиск

Основание: [Чаты и память](https://github.com/Ayuemin/Ayuemin-obsidian-/blob/main/Ilmar/Чаты%20и%20память.md) и [Модели и экономия токенов](https://github.com/Ayuemin/Ayuemin-obsidian-/blob/main/Ilmar/Модели%20и%20экономия%20токенов.md). История не ограничивается окном модели: Ilmar должен циклически обновлять рабочий контекст **в том же чате**, сохраняя оригиналы отдельно. Физическое окно одного API-вызова остаётся конечным; оно не является пределом длины диалога.

## Изменения после скриншотов сборки 9

- Контекст по умолчанию берётся из каталога модели. Фиксированные 8192 больше не являются значением по умолчанию; если каталог не сообщил окно — используется резервное значение 32768. Явно сохранённые пользователем значения сохраняются. В настройках памяти можно указать `0` для автоматического окна и резерва ответа.
- Автоматическое сжатие работает циклически при приближении к заполнению. Если предпочтительное число последних сообщений не помещается, сжимается больший префикс, последний вопрос сохраняется. Оригинальная история, вложения, правила и предыдущие версии сводок не переписываются.
- При неудачном автоматическом Compact используются явно помеченные локальные выдержки, предыдущие факты/решения и поиск оригиналов; это не называется успешной модельной сводкой. Неудача и причина записываются в журнал. Ручной некорректный Compact сообщает свою ошибку и сохраняет прежнюю сводку.
- Если сводка не короче, она не заменяет прежний контекст; это информационный статус, а не блокирующая ошибка. Сравнивается новая рабочая сводка с предыдущей сводкой плюс новым участком. Для короткой истории Compact может не дать экономии.
- Большие сообщения и вложения в рабочем запросе представлены обозначенными выдержками. Полный текст читается через `read_file(file_id, offset, limit)`; `message:<id>` читает оригинал сообщения. Если переданы только некоторые страницы/изображения, модель получает явное уведомление об этом и не должна объявлять весь документ просмотренным.
- Полные исполненные раунды tools сохраняются в SQLite, а их рабочая история сокращается **целыми** call/result группами. В модель не попадают оборванные пары и скрыто обрезанный JSON вызова. Справка содержит `trace_id`, имена инструментов, file_id/ошибки; `read_file("trace:<id>", offset, limit)` читает оригинал в пределах того же чата.
- SQLite v4 → v5 добавляет `tool_traces`, v5 → v6 — производный семантический индекс, не пересоздавая сообщения, вложения, usage и память. Очистка/удаление чата удаляют его trace.
- Файл появляется в UI после завершения tool round, до окончательного текста модели. После ошибки задачи можно повторить запрос и при наличии промежуточного сообщения-файла; такой файл не превращается в запрет повтора.
- Неверный JSON/тип аргументов и неизвестное имя tool возвращаются модели как конкретная ошибка для исправления. Отзыв разрешения, повтор без прогресса и реальные исчерпанные бюджеты останавливают задачу с точной причиной, а не общей фразой про любые возможные ошибки.

Сжатие вероятностное: оригиналы и поиск нужны для восстановления деталей. Непрерывный чат не означает, что модель одновременно помнит каждый байт архива. Правила пользователя передаются отдельно дословно. Если одни неизменяемые правила/схемы занимают всё физическое окно, нужна другая модель или меньший набор одновременно включённых инструментов; новый чат не предлагается как решение длины истории.

## Карточка состояния и архивный поиск

Документы Obsidian требуют **полного сохранения истории**, отдельной видимой capsule/контрольной точки и поиска. Векторный RAG указан следующим этапом после SQLite FTS. Реализация сохраняет это разделение:

- В карточке памяти чата доступны цель, план (новые сводки), факты, решения, прогресс, файлы/версии, проверки, ошибки, следующий шаг и неопределённость. Правила и утверждённые решения хранятся отдельно; версии сводки можно просматривать, переключать и удалять без удаления оригиналов.
- «Найти на устройстве» выполняет локальный SQLite FTS без API. «Найти по смыслу (API)» использует дополнительный индекс. `search_history(query, mode)` даёт агенту оба способа поиска после отдельного включения инструмента; `read_file(message:<id>)` читает найденный оригинал.
- Настройки → Память → **Поиск по смыслу в архиве (RAG)**: отдельный провайдер, ID модели эмбеддингов, опциональный полный URL `/embeddings`. Модель эмбеддингов не является моделью Compact. Поддержан OpenAI-compatible JSON API; ключ берётся из защищённого подключения.
- По умолчанию API-эмбеддинги выключены. При явном включении текст старых сообщений и текстовых вложений, а также поисковый запрос передаются выбранному провайдеру. Это отдельные расходы **вне локального бюджета генерации**; используйте квоту провайдера. Иллюстрации без извлечённого текста не индексируются как визуальные векторы.
- Архив старше последних N сообщений индексируется в фоне при открытии/выборе чата, открытии карточки памяти и после ответа. Последние сообщения остаются дословными в рабочем контексте. Есть кнопка обновления индекса и статус прогресса/ошибки. Индексация выполняется, пока жив процесс приложения; Android WorkManager для продолжения после убийства процесса пока не добавлен.
- Фрагменты по 2000 символов с перекрытием 200, пакеты по 16; размеры/таймауты и бюджет найденных фрагментов меняются в расширенных лимитах. Векторы нормализованы, записаны в локальный SQLite. Выборка — точное cosine-ранжирование с ограниченной RAM; время поиска растёт с числом фрагментов. ANN/pgvector и внешний сервер не используются.
- Индексы изолированы по chatId, провайдеру, endpoint, модели и настройке чанкинга; смена модели не смешивает несовместимые векторы. Ранее оплаченные сохранённые пакеты не покупаются повторно при возобновлении. Для прерванного сетевого запроса до получения/записи результата повторная оплата зависит от API; exactly-once не обещается.
- При подготовке рабочего контекста семантические и FTS-фрагменты подбираются только из сжатого префикса и ограничиваются свободным бюджетом. Пустой/недоступный семантический индекс оставляет FTS и карточку состояния рабочими. Сбой индексации не останавливает ответ.
- Очистка/удаление сообщения или чата удаляет соответствующие производные векторы. Завершившийся позже сетевой запрос не воскрешает удалённую историю. Старые пространства индекса после смены модели пока сохраняются до удаления/очистки чата.

## Глобальные расширенные лимиты

Настройки → **Расширенные лимиты**. Значения действуют для всех чатов; ранее отсутствовавшие настройки получают расширенные defaults.

- Агент: 64 раунда, 256 tool calls; время задачи и модельного запроса по умолчанию без ограничения; tool — 120 секунд. Раунды, вызовы, время и защиту повторов можно отключить значением 0. Остановка пользователем сохраняется.
- Аргументы tool — 16 МиБ, результат — 2 МиБ; рабочая история — 12000 оценочных токенов с автоматической проекцией под окно модели. Все эти значения меняются в UI.
- Создание UTF-8 файла — 16 МиБ вместо 32 КиБ; импорт — 128 МиБ; извлечённый текст — 8 МиБ; 32 вложения; 100 страниц PDF. Отдельно настраиваются XML/ZIP, листы, ячейки и изображения. Квота создания файлов по умолчанию отключена.
- Fetch/search — 8 МиБ ответа и 60 секунд вместо 1 МиБ/15 секунд; число результатов, длина выдаваемого текста и кэш настраиваются.
- Память: квота числа фактов по умолчанию отключена; размер факта, число шагов плана, вывод Compact, допустимый размер сводки и журнал также настраиваются.
- Токеновый бюджет задачи по умолчанию отключён (`0`); денежный бюджет опционален. Эти настройки — в разделе памяти. API-квоты, реальные возможности модели, авторизация и защита локальных сетей сохраняются.
- Структурные защиты парсеров, имён/путей и недоверенного содержимого не снимаются. Повышение лимита размера не создаёт дополнительную RAM и не увеличивает физическое окно API.

## Файлы без двойного расширения

`demo_tools.md` больше не предлагается системному picker как `text/plain` с каноническим `.txt`. Для Markdown/Python/Kotlin используются подходящие MIME в метаданных. При несовпадении канонического расширения Android с уже указанным именем экспорт использует `application/octet-stream`, сохраняя исходное Unicode-имя. HTML/SVG/XML по-прежнему только сохраняются. Старые имена в сохранённой истории и уже экспортированные пользователем файлы не переименовываются автоматически.

## Диагностика и выгрузка

Настройки → **Диагностика**: читаемые даты, фильтр ошибок, обновление, выгрузка `.jsonl` через системное сохранение и очистка с подтверждением. По умолчанию хранятся 2000 событий с подробностями до 65536 символов на строковое поле; на экране показаны последние 200 событий, выгрузка включает весь сохранённый журнал и старые tool logs.

В журнале: модель/провайдер/host, request_id, назначение answer/compact, оценка входа, latency, finish_reason, usage/cost при наличии, вызовы tools с аргументами/результатами, trace_id, тип исключения и stack trace. Ошибки контекста/сжатия/инструмента/таймаута не называются NETWORK_ERROR. Тела HTTP-ошибок моделей сохраняются ограниченно и очищаются от известных ключей/заголовков. Неизвестная стоимость остаётся неизвестной.

API-ключи и пользовательские HTTP-заголовки поиска не выводятся; чувствительные поля и Bearer/sk-токены редактируются. Подробный журнал может содержать текст пользовательских файлов и запросов — это явно указано рядом с выгрузкой. Полная история промпта модели по умолчанию не копируется в диагностику. Старый краткий журнал доступен в выгрузке.

## Любой совместимый поисковый API

Настройки → Инструменты → **API поиска**. Сохраняются несколько профилей; один активен глобально. Существующий ключ Brave продолжает работать без переноса пользователем.

- Шаблоны Brave, Tavily, SerpAPI и пользовательский HTTPS JSON API.
- GET: endpoint, query-параметр или URL-шаблон.
- POST: настраиваемое JSON-тело.
- `{query}`, `{api_key}`, `{count}` подставляются с корректным URL/JSON-кодированием. `{count}` в JSON преобразуется в число, а не строку.
- Произвольные HTTP-заголовки, включая Authorization, хранятся зашифрованно отдельно от метаданных профиля. Ключ — отдельное защищённое поле; в URL/теле используется placeholder.
- Путь массива результатов и поля title/URL/snippet: dotted path или JSON Pointer. Пример: `data.items`, `/data/items`, `document.title`.
- Кнопка проверки выполняет один реальный запрос выбранного профиля; цена зависит от API. Отсутствующая схема ответа вызывает понятную ошибку с нужным путём.
- Локальные/служебные адреса, встроенные пароли и перенаправления запрещены, включая пользовательский поиск. Публичный HTTPS на нестандартном порту разрешён. Недоверенные snippets не считаются инструкциями приложения.

Под «любым» здесь понимается настраиваемый HTTPS JSON API с GET/POST. XML/SOAP, сложные OAuth-потоки и собственные бинарные протоколы требуют отдельного адаптера; скрытая универсальность не заявляется.

## Проверка на устройстве

1. В памяти установить окно `0` и автоматическое сжатие, обновить каталог. Продолжить прежний чат до нескольких циклов Compact; chatId/история/правила/файлы должны сохраниться.
2. На коротком чате нажать Compact: отсутствие экономии должно стать статусом без блокировки следующего запроса.
3. Создать `demo_tools.md`, `Отчёт.py`, CSV/JSON, сохранить и проверить имя в файловом менеджере. Повторить после перезапуска и поворота экрана.
4. Увеличить глобальные лимиты и проверить файл >32 КиБ; прочитать его частями, сравнить с оригиналом. Проверить повтор задачи после промежуточного файла и ошибки.
5. Выгрузить журнал после ошибки; найти request_id, конкретный tool/Compact и причину. Убедиться, что в выгрузке нет ключей.
6. Включить эмбеддинги, выбрать провайдера/модель; дождаться индекса. Сравнить FTS и смысловой поиск по вопросу без общих слов с оригиналом; прочитать исходное сообщение. Выключить API/сменить модель/удалить чат — история и индексы должны оставаться изолированными.
7. Настроить второй поисковый API, проверить GET/POST, вложенные поля и смену активного профиля. Без ключа для API, требующего ключ, поиск должен оставаться недоступным.

Локальные Unit/Robolectric, lint и сборка проверяются отдельно от GitHub CI и но не заменяют реальную проверку провайдеров, Android picker, Keystore и интерфейса на телефоне.
