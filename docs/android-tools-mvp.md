# Android tools: реализация и границы

База: `codex/chat-preview-registry`, `5c032482`. По решению пользователя серверные функции отложены: Ilmar остаётся Android-приложением без обязательного бэкенда.

## Исправления чата

- «Спросить снова» добавляет выбранный старый запрос с его вложениями в конец того же чата. В API идёт текущая история. Последний неотвеченный запрос повторяется без дублирования. Явное «Ответвление» по-прежнему создаёт новый чат.
- Черновик текста и черновые вложения при повторе сохраняются. Исходные сообщения, платный usage и настройки чата не копируются в новый чат.
- Текст пользователя выровнен по началу строки, фон — 4% `onSurface`.
- Настройки → Память и контекст → отдельный каталог провайдеров/моделей Compact. Выбор сохраняется по стабильному ID. По умолчанию используется модель чата. У Compact свои endpoint, ключ, окно контекста, лимит вывода и тарифы; общий бюджет задачи остаётся общим. Недоступная выбранная модель не подменяется автоматически.

## Доступные native tools

Сначала разрешить инструмент глобально в настройках, затем выбрать в `+` текущего чата и включить агента у модели с подтверждённой поддержкой tools. Разрешение повторно проверяется перед каждым исполнением. Brave дополнительно требует ключ; быстрый переключатель интернета использует тот же агентный путь.

| Инструмент | Реализация | Ограничения |
|---|---|---|
| `web_search(query)` | Brave Search API: заголовки, сниппеты и URL | 5 результатов, запрос до 1000 символов; ключ в Android Keystore |
| `fetch_url(url)` | OkHttp + Jsoup: article/main или body без script/style/nav | Публичное доменное имя HTTPS:443, запрет private/special IP при DNS-разрешении, без IP literal, перенаправлений и HTTP proxy; 15 с, 1 МБ распакованного ответа, до 24 тысяч символов текста |
| `read_file(file_id)` | Только вложения сообщений выбранного чата; пустой ID возвращает список | До 24 тысяч символов; PDF и фото читаются уже существующим vision-входом, а не притворным OCR |
| `calculator(expression)` | Собственный ограниченный арифметический парсер | `+ - * / % ^`, скобки, научная запись; Double, 2048 символов, глубина 32, 512 операций; нет eval/runtime |
| `create_file(name, content)` | UTF-8 файл в приватном хранилище + постоянное сообщение-вложение | txt/md/csv/json/html/xml/yaml/py/js/kt/svg, до 32 КБ, квота создания 100 МБ; имя без путей и управляющих символов |
| `save_memory(text)` / `recall_memory(query)` | SQLite FTS, область одного чата | 200 записей по 4000 символов; до 8 совпадений; **эмбеддинги не реализованы** |
| `todo(steps?)` | Сохраняемый JSON-план чата | До 30 шагов, не больше одного in_progress; не запускает фоновые задачи |
| `ask_user(question)` | Прерывает текущую агентную задачу и сохраняет вопрос как сообщение | До 2000 символов; следующий ответ пользователя начинает новую задачу с историей, продолжение tool_call не имитируется |

Вложения: существующие TXT/MD/CSV/JSON, DOCX, изображения и PDF до 12 страниц сохранены. Добавлен XLSX: shared strings, inline strings и кэшированные значения ячеек. Формулы и макросы не выполняются, форматирование дат/чисел не воспроизводится. Ограничены число компонентов ZIP, суммарная распаковка, размер XML, число листов/ячеек и извлечённого текста; DTD запрещён.

## Файлы на Android

- `create_file` возвращает `file_id`, имя и MIME. Повтор того же имени/содержимого в чате возвращает существующий файл.
- Файл и его ID сохраняются в сообщении SQLite и доступны после перезапуска; существующие правила общей ссылки веток/очистки вложений сохраняются.
- «Сохранить» использует системный `ACTION_CREATE_DOCUMENT`, имя передаётся Unicode, байты копируются только в выбранный пользователем URI. Расширение и правильный MIME сохраняются в метаданных.
- HTML/SVG/XML не открываются встроенным просмотром или ACTION_VIEW: только явное сохранение.
- HTTP endpoint, Content-Disposition, подписанный URL и TTL не нужны для локального экспорта и **не реализованы**. Приватный FileProvider выдаёт другим приложениям временное разрешение чтения при явном открытии обычного вложения.
- Создание файла ограничено 32 КБ и общей квотой 100 МБ существующих вложений. Это квота создания, не новая квота импорта: существующий импорт по 20 МБ сохранён. Удаление последней ссылки удаляет файл; при старте удаляются потерявшие ссылки файлы. Cron отсутствует.

## Защиты и инфраструктура

- Существующие лимиты: 8 модельных раундов, 24 вызова, 180 секунд на задачу, 20 секунд на tool. Размер аргументов/результата ограничен 64 КБ **UTF-8 байт**, а не числом Kotlin Char. Повторяющиеся действия без прогресса останавливаются.
- Схемы аргументов отправляются модели; native tools дополнительно проверяют обязательные поля, лишние поля и типы перед исполнением. Передаётся только разрешённый для чата набор.
- `GenerationOptions.responseSchema` добавляет явный `response_format: json_schema` с strict=true. Параметр опциональный: вызывающий код должен выбирать совместимую модель. Обычный чат и Compact не получают его автоматически.
- Search/fetch имеют локальный кэш на 5 минут, максимум 32 записи; одновременная загрузка сериализуется. Неуспешные вызовы не кэшируются. Цена Brave неизвестна приложению, ноль не выдумывается. Локальный бюджет USD охватывает модельные запросы, а не оплату поискового API; для Brave действует лимит числа tool calls и квота самого провайдера.
- Последние 100 вызовов записываются локально: инструмент, чат, до 2048 символов аргументов/результата, latency и status; cost=NULL. Ключи HTTP не входят в аргументы и журнал. Аргументы могут содержать личный текст пользователя; это явно указано в настройках. Удаление чата удаляет его память, план и журнал.
- Native tools — доверенный ограниченный Kotlin-код внутри приложения. **Отдельные процессы/сервисы для каждого инструмента не реализованы; это не sandbox для произвольного кода.**
- Письма, платежи, OAuth-операции и произвольный Shell не реализованы. Кнопки подтверждения таких действий появятся вместе с реальными исполнителями; модель не может выдать себе разрешение.

## Отложено

- Docker/no-network sandbox, Run code, серверные storage/download endpoints, presigned URL/TTL/rate limit и cron — по решению пользователя.
- Эмбеддинги и векторный RAG базы знаний с чанкингом/реранкером. Локальный поиск памяти/истории не называется векторным RAG.
- Image generation как реальное создаваемое изображение; отдельные облачные STT API. Существующие vision, системная диктовка и системная/API TTS сохранены.
- Email/Calendar/CRM через OAuth; Maps/Weather/Currency по отдельным требованиям и выбранным поставщикам.
- Отдельный isolatedProcess/IPC для недоверенных расширений.

## Телефонная приёмка

1. Повторить ранний и последний неотвеченный запрос; проверить один chatId, сохранность истории, черновика и вложений после перезапуска. Явное ответвление должно по-прежнему создавать чат.
2. Выбрать отдельную модель Compact другого провайдера; сжать длинный чат и проверить usage/ошибки подключения. Затем обычный ответ должен использовать прежнюю модель чата.
3. Выдать отдельные разрешения tools; выбрать набор для чата, включить агента. Без глобального разрешения или при его отзыве вызов должен блокироваться.
4. Настроить настоящий ключ Brave; проверить сниппеты/URL и повтор из кэша. Проверить публичный fetch, отказ localhost/private IP, redirect, превышение размера и отмену.
5. Создать «Отчёт.html» и CSV, перезапустить приложение, сохранить через Android picker. HTML не должен открываться внутри приложения. Проверить отмену picker и отказ в доступе.
6. Прочитать XLSX с русскими ячейками, DOCX, PDF и фото на поддерживаемой vision-модели. PDF/изображения не должны отправляться модели без image capability.
7. Сохранить память/план, перезапустить, проверить изоляцию другого чата. Ask user должен сохранить вопрос и завершить активную задачу.

Реальный Brave/LLM API, Keystore и системный picker требуют проверки на устройстве; unit-тесты этого не заменяют.
