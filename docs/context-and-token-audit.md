# Проверка памяти и экономии токенов — 2026-10-20

Источники требований: Obsidian `Ilmar/Модели и экономия токенов.md`, `Ilmar/Чаты и память.md`. Это отчёт проверки, не второй Roadmap.

| Требование | Фактическое состояние |
| --- | --- |
| История независимо от окна модели | SQLite хранит полные сообщения. Вложения — отдельные приватные файлы. Версия 3 добавляет ссылки/метаданные без пересоздания истории. |
| Рабочий контекст как проекция истории | Не реализован: ChatViewModel передаёт всю историю выбранного чата в GenerationPayload. |
| Автоматический Compact при 75–85%, ручной Compact | Не реализованы; сводок и capsule в базе нет. |
| Последние N полных сообщений без изменений | Не реализовано. Новое ответвление копирует точный префикс истории, но не сжимает его. |
| Отдельные правила, инварианты, checkpoint задачи | Не реализованы. active_chat/active_request — отметки прерывания, не восстановление задачи. |
| Общий бюджет system + tools + вложения + резерв ответа | Не реализован. context_length/max_output сохранены из каталога, но не управляют размером запроса. Ограничение размера изображения — защита транспорта, не токеновый бюджет. |
| Prompt caching | Нет явных cache_control/TTL/провайдерной политики. Провайдер может автоматически кэшировать совпадающий префикс. Факт определяется только по cached_tokens. Заявлять, что Ilmar включил caching, нельзя. |
| Фактический usage/стоимость | Реализованы, данные сохраняются на каждый модельный вызов. Неизвестные значения не заменяются нулём. Кэшированные токены отдельно; денежная экономия без тарифов не рассчитывается. |
| Каталог метаданных | Локальный кэш моделей, stable ID, избранное, явное обновление. TTL/индекс репозитория/кэш инструментальных чтений пока отсутствуют. |
| Схемы инструментов по требованию | В обычном чате схем нет. В агенте передаются только установленные, выбранные и разрешённые инструменты. Search → describe → execute ещё нет. |
| Лимиты | Есть пределы раундов/вызовов/времени, защита повторов и отмена. Денежного и токенового бюджета задачи пока нет. |
| Поиск | Поиск по загруженной истории в UI. SQLite FTS/RAG отсутствуют. |
| Сжатие логов/больших результатов | Вывод инструмента ограничен, но отдельное хранение полных результатов и сводки ещё не реализованы. |

Следующая реализация по требованиям: отдельная проекция контекста и оценка всех составляющих с резервом ответа → сохраняемые версии capsule и неизменяемые правила → ручной/автоматический Compact в существующей очереди с отменой/восстановлением → провайдерная политика caching → измерение фактической экономии и сохранности фактов. Нельзя просто обрезать старые сообщения или объявить ветвление сжатием.

Повтор, ветвление и вложения в этой правке не изменяют полную исходную историю. API-озвучка — отдельная платная операция; её тариф пока не включается в статистику генерации ответа (это указано при выборе).
