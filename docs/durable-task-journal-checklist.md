**Ограничения:** Android без собственного сервера; полная история и вложения сохраняются. Единственный Roadmap — [Obsidian/Ilmar/ROADMAP.md](https://github.com/Ayuemin/Ayuemin-obsidian-/blob/main/Ilmar/ROADMAP.md). Этот файл — технический чек-лист исполнения, а не второй Roadmap.

## Этап 1 — пункты 1–2 (приоритет Codex)

### 1. Сохранять подтверждённое состояние задачи
- [ ] Хранить постоянные идентификаторы задачи, шага и вызова инструмента, статус, результат и ссылки на созданные файлы.
- [ ] Передавать следующему модельному запросу компактную сводку **фактически выполненных** действий.
- [ ] Явно разделять подтверждённые результаты, предположения и модельную сводку.

### 2. Исправить повтор после сбоя
- [ ] Повтор выполняется в **том же чате**.
- [ ] Уже успешные побочные действия автоматически повторно не выполняются.
- [ ] Для оборванной операции с неопределённым исходом показывается статус неопределённости, без выдуманного успеха или автоматического повтора.
- [ ] Проверить восстановление после сетевого сбоя и перезапуска приложения.

## Этап 2 — пункт 3: файлы и план
- [ ] Отличать повтор создания идентичного файла от намеренного создания новой версии.
- [ ] Не перезаписывать и не удалять файлы без явного действия.
- [ ] Присвоить шагам плана постоянные ID; перестановка не сбрасывает статусы.
- [ ] Показывать в карточке состояния актуальный план и подтверждённые результаты.

## Этап 3 — пункт 4: индексация
- [ ] Объединять несколько сообщений в один запрос эмбеддингов.
- [ ] Не делать отдельный запрос эмбеддингов для каждого «далее».
- [ ] Сохранять короткие содержательные сообщения при подготовке индекса.
- [ ] Раздельно управлять остановкой генерации и фоновой индексации.
- [ ] Возобновлять индексирование без повторной оплаты **уже сохранённых** эмбеддингов; не обещать exactly-once для оборванного внешнего запроса.

## Этап 4 — пункт 5: импорт и диагностика
- [ ] Принимать собственный экспорт `.jsonl`, включая `application/octet-stream`.
- [ ] Пояснять в журнале единицы измерения, область действия лимитов и значение `0`.
- [ ] Добавить ID запуска задачи, связь повторов, параметры рабочего окна и Compact.
- [ ] Записывать доступные cached tokens и стоимость эмбеддингов; неизвестную стоимость не заменять нулём.

## Этап 5 — пункт 6: непрерывный контекст
- [ ] Регрессионный сценарий нескольких автоматических Compact в **одном** длинном чате.
- [ ] После Compact сохранять правила, план, файлы и восстановление деталей через FTS/RAG.
- [ ] Сбой Compact или эмбеддингов не удаляет историю и не блокирует чат навсегда.

## Приёмка каждого этапа
- [ ] Регрессионные тесты затронутых сценариев без платных API.
- [ ] Unit/Robolectric, Android lint и сборка APK.
- [ ] Проверить GitHub Actions для соответствующего коммита и устранить ошибки до отметки о завершении.
- [ ] Проверка на телефоне отдельно от автоматических тестов.
- [ ] Зафиксировать проверенные результаты, ограничения и следующий шаг в **единственном** Roadmap Obsidian.

## Правила реализации
- Не переписывать существующие Compact, FTS/RAG, tool traces, UI и SQLite без доказанной необходимости.
- До изменений прочитать `AgentRecoveryTest`, `AgentLoopRunner`, `ChatStore`, `ChatViewModel`, `ToolHistoryProjection`, существующие миграции и архитектурные документы «Чаты и память», «Модели и экономия токенов».
- Для внешних побочных эффектов различать подтверждённый результат и неопределённый исход. Автоматический повтор разрешён только при доказанной безопасности.
- Галочка означает **проверено**, а не «написан код».
