# Проверка браузера и поиска в чате

Это техническая процедура, не второй Roadmap. Единственный Roadmap:
https://github.com/Ayuemin/Ayuemin-obsidian-/blob/main/Ilmar/ROADMAP.md.

## Реализация

Подход WebView/DOM/human handoff адаптирован из Ayuemin/Umnik,
LocalBrowserRuntime.kt и LocalBrowserHost.kt (main a72bf3603710d11fe5827eade3559c262d77bc15). В Ilmar он разделён на Android-адаптер,
сессию, фиксированные JS-команды, снимки, инструменты, поиск и Compose-интерфейс.
Монолит Umnik и остальные его зависимости не переносились.

В меню «+» поиск включается независимо от агента. Нажатие на значок поиска открывает
выбор: авто, поставщик или локальный браузер. Авто до запроса выбирает доступный
встроенный поиск, иначе WebView. Ошибка поставщика не вызывает скрытый второй запрос.

Адаптеры поставщиков: совместимый Chat Completions web_search_options, встроенный
поиск модели и OpenRouter web plugin. Протокол настраивается на подключение. Для API,
не публикующих возможности модели, tools и vision можно подтвердить явно для её ID;
остальные модели не меняются. «Вернуть сведения каталога» снимает переопределения.
Этот переключатель не добавляет отсутствующие функции самому API/модели.

Браузер умеет поиск, HTTPS-навигацию, чтение/прокрутку, назад, клики по DOM ref или
координатам 0–1000 viewport, обычный ввод, выбор option и отправку формы. Page ID и
стабильные refs защищают от нажатия элемента из устаревшего документа. Ответ после
клика не является доказательством завершения действия на сервере. Опасные действия
проходят через Durable Task Journal. При UNKNOWN browser click/type/select новые
автоматические записи браузера блокируются даже после смены page/ref IDs при reload.
Чтение и ручное управление доступны; автоматического снятия неопределённости нет.
SUCCEEDED переиспользуется по существующему каноническому ключу аргументов задачи;
семантическое равенство разных кликов не доказано.

Пароли/коды/CAPTCHA и распознанные опасные подтверждения передаются пользователю.
Кнопка «Готово, вернуть модели» добавляет явное подтверждение и продолжает ту же
задачу. Пока управление у пользователя, команды и снимки модели заблокированы.
Значения полей ввода не включаются в DOM-снимок. Модель не вводит пароли или коды;
пользователь вводит их непосредственно в WebView. Cookies остаются в WebView.

Vision-модель может запросить screenshot: viewport до 1600 px по длинной стороне.
Оригинал и нормализованное изображение остаются вложением чата. Флаг browser_observation
не даёт повторно отправлять старые снимки с полной историей. Один кадр поступает в
ближайший модельный запрос после tool result; окно резервирует оценку картинки,
денежный preflight использует существующие ограничения для изображений. В trace и
диагностику попадают IDs, а не base64. Ручной ввод/страница с password или CAPTCHA не
снимаются моделью. После остановки/очистки задачи поздняя запись кадра блокируется.

## Телефонная приёмка — открыта

1. Установить APK из успешного CI, проверить versionCode 12 и SHA в диагностике.
   Подпись сверить по apk-update-report. Без совпадающего сертификата обновление
   поверх установки невозможно; владелец разрешил чистую установку для теста.
   Удаление уничтожает старые приватные данные и ключи.
2. Выключить агента. Включить поиск → локальный браузер у модели с tools. Попросить
   найти источник, открыть ссылку, прокрутить и нажать элемент/заполнить поисковую форму.
3. Проверить на двух разных поставщиках: настроенный протокол встроенного поиска,
   browser, auto и явную ошибку неподдерживаемого протокола. Проверить сохранение
   настроек по подключениям/моделям; ошибка не должна запускать второй платный запрос.
4. На тестовой странице входа дождаться передачи экрана. Ввести данные на странице,
   выполнить CAPTCHA/подтверждение, вернуть управление кнопкой. Проверить сохранение
   task ID, новый parent-linked run и отсутствие повторного уже выполненного клика.
   Не присылать пароли/коды в чат или диагностику.
5. Выбрать модель с tools+image. Попросить снимок и описать визуальную деталь сложной
   страницы; затем клик по координатам. Проверить картинку в чате, поддержку зрения,
   отсутствие повторной передачи изображения на каждом ходе и честный учёт usage.
6. Проверить stop, таймаут, ошибку загрузки, поворот, переход между чатами, перезапуск,
   Compact и сохранность истории/изображений. Проверить блокировку снимков/действий
   во время ручного управления и отсутствие приватных адресов/file/content навигации.

Реальный WebView/рендеринг/координаты/сайты/вход/CAPTCHA/совместимость провайдеров
не приняты до телефонного теста. Это foreground WebView, не фоновый браузерный сервис.
Не перенесены автоматические загрузки файлов, файловый upload, HTTP Basic Auth,
обход защит сайтов и произвольный JS/shell. Сложный сайт может потребовать ручного
управления; exactly-once внешних действий и универсальное распознавание CAPTCHA не обещаны.
